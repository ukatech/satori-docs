# 辞書の静的検査（ShioriLint）

Mc206-1以降。辞書を実行せずに調べて、書き方の誤りや、存在しない飛び先・単語群を一覧で返します。これまで実行してみないと分からなかった誤り（`＞` の飛び先の書き間違い、閉じ忘れた `（`、`（笑）` のような名前の誤読など）を、ゴーストを動かさずに見つけられます。

## 使い方

`ID: ShioriLint` のリクエストを `SecurityLevel: local` で送ります。デバッグモード（`＄デバッグ＝有効`）は要りません。何も実行しない（SAORI を呼ばない、変数を変えない、乱数を引かない）ので、ゴーストの状態は変わりません。

```
GET SHIORI/3.0
Charset: UTF-8
Sender: SSP
SecurityLevel: local
ID: ShioriLint

```

- `SecurityLevel: local` 以外では動作せず、`403 Forbidden` を返します（[＄外部から実行可能なイベントの接頭辞](../system/vars-misc.md#外部から実行可能なイベントの接頭辞)に `ShioriLint` が当てはまると、external でも local 扱いになります）。
- SSP を起動せずに、動作確認用の `harness`（`satoriya/test/harness/`）のように `satori.dll` を直接呼んで使えます。

## さとりてから実行する

Mc206-2以降。さとりて（`satorite.exe`）なら、リクエストを組み立てずに検査できます。さとりては、置いたフォルダ（ゴーストの `master` フォルダ）の辞書を調べます。`SecurityLevel: local` のリクエストを自分で送るので、デバッグモードも要りません。

- **「検査」ボタン**: 辞書を読み直して検査し、結果を下の出力欄に 1 件 1 行で表示します。最後の行に、エラーと警告の件数が出ます。辞書を編集したあとに押せば、その内容で調べ直します。
- **`satorite.exe --lint`**: ダイアログを出さずに検査して終了します。ダイアログを開いたままでも実行できます。

```
dic_a.txt(2) : warning: 「存在しない名前」は、単語群・文・変数・内蔵関数・SAORIのどれにも見つかりません。…
dic_a.txt(4) : error: 計算式が正しくありません：「１＋」
検査が終わりました。エラー 1 件、警告 1 件
```

`--lint` の終了コードは、`error`（読み込み時の重大なエラーを含む）が 1 件でもあれば 1、なければ 0 です。`warning` と `notice` だけなら 0 です。結果の出力先は、起動のしかたで決まります。

- コンソール（コマンドプロンプト・PowerShell）から起動したときは、そのコンソールに出ます。
- パイプやファイルにリダイレクトしたときは、親のコンソールの出力コードページ（PowerShell なら `[Console]::OutputEncoding`）で書きます。親にコンソールが無いときは、システムの ANSI コードページ（日本語環境なら Shift_JIS）です。
- コンソールにもリダイレクトにもつながっていない起動（ショートカットなど）では、メッセージボックスに出します（長いときは 3000 文字で切ります）。

さとりては Windows アプリ（GUI サブシステム）なので、コンソールからそのまま呼ぶと、シェルは終了を待たずに次へ進みます。終了コードを使うときは、待たせてください。

```
start /wait satorite.exe --lint
```

PowerShell では `Start-Process -Wait -NoNewWindow satorite.exe --lint`、または `satorite.exe --lint | Out-Host` とします（パイプにつなぐと、出力が閉じるまで待ちます）。

## 応答

`Value` は返りません。結果は SHIORI/3.0 の `ErrorLevel` / `ErrorDescription` ヘッダで返ります。問題が 1 件も無いときは、どちらも付かない 200 OK です。

| ヘッダ | 内容 |
|--------|------|
| `ErrorLevel` | 問題ごとの重さ。`error` `warning` `notice` のどれか（省略の知らせだけ `info`）。バイト値 1 で区切って並ぶ |
| `ErrorDescription` | 問題ごとの説明。バイト値 1 で区切って並ぶ。`ErrorLevel` と要素数・順番が同じ |

ベースウェアが `capability` で `response.errorlevel` を通知したかどうかに関係なく、常に返ります（ふだんのエラー通知は、通知したときだけです）。下の例では、バイト値 1 を `␁` で示します。

```
SHIORI/3.0 200 OK
Charset: UTF-8
ErrorLevel: warning␁error␁error
ErrorDescription: dic_a.txt(3) : warning: 「存在しない名前」は、単語群・文・変数・内蔵関数・SAORIのどれにも見つかりません。（ を文字として表示するときは φ（ と書きます。␁dic_a.txt(4) : error: ジャンプ先「存在しないトーク」という＊の文がありません␁dic_a.txt(10) : error: 計算式が正しくありません：「１＋」
```

- 説明の形式は `ファイル(行) : error: 内容` / `warning: 内容` / `notice: 内容` です。ビルドツールのエラー出力と同じ形なので、エディタやCIの問題一覧に取り込めます。
- 問題の数とエラーの数は、要素の数と `error` の数で分かります。
- ファイル名は、ゴーストの `master` フォルダからの相対パスで、区切りは `/` です。
- 行は、元ファイルの行番号（1 始まり）です。`（` が複数行にまたがるときは、その `（` を含む論理行の先頭の行になります。
- 1 ファイルのうち、辞書全体にかかわる問題（`（` の閉じ忘れなど）は、そのファイルの個々の行の問題より先に出ます。
- 説明の中の改行とバイト値 1 は、区切りと混ざらないよう空白に置き換えます。
- メッセージは最大 1000 件までです。`notice` は 100 件まで、`warning` と `notice` は全体が 800 件に達するまでで、残りの枠は `error` のために空けてあります（`error` が多い辞書でも、後ろのほうの `error` が押し出されません）。超えた分は、最後の要素（`info`）が `ほかN件は省略しました`（`error` が含まれるときは `（うち error M件）` も）と知らせます。
- 同じ内容がログ（`lint: …`）にも出ます。

## 調べる対象

- 読み込まれた辞書です。`satori_conf.txt` と、`辞書フォルダ` を含む読み込みの規則で読まれた辞書ファイル（接頭辞・拡張子・`.sat` も含む）が対象です。セーブデータは含みません。
- **`＄辞書フォルダ` で読むフォルダを絞っている（セーブデータに残っている場合も含む）と、そのフォルダの辞書だけが対象です。** 読み込んでいない辞書は調べません。
- ファイルは検査のたびに読み直します。読み込んだ後に辞書を書き換えていても、書き換えた内容が検査されます。読み込み時と同じ手順（文字コードの判定、`.sat` の復号、`φ` と `＃` の処理、`replace.txt` の置き換え、カッコ内の改行の連結）で読むので、実際に動くときと同じ解釈になります。

## エラーと警告

- **error**: 書き方として誤りで、実行すると意図どおりにならないことが、辞書の字面だけで確実に言えるもの。
- **warning**: 誤りの可能性が高いが、断定できないもの、または動作はするが避けたほうがよいもの。
- **notice**: 書き方としてありうる（ひな形が用意する任意のフック、表示したい記号など）ため、誤りとは限らないもの。意図と合っているかの確認用。

重さは、約 1,600 本のゴーストの辞書に通して、誤検出が多い型を下げて決めています。`error` は、実行しても意図どおりにならないことが確実なものに限ります。

### error

| 検出するもの | メッセージ |
|--------------|------------|
| `＄` の行にタブも `＝` も無い | `＄による変数代入文には、タブによる区切りか、＝による計算式が必要です` |
| 数字だけの変数名 | `「名前」　数字のみの変数名は扱えません` |
| 式が計算できない | `計算式が正しくありません：「式」` |
| 内蔵関数の引数の個数が違う | `「set」の引数の個数が正しくありません（1個）` など |
| 特殊形式（`when` `whenlist` `times` `while` `for`）の引数の個数が違う | `引数の個数が正しくありません（4個）` |
| 閉じていない `（` | `（ に対応する ） がありません`、`（ が閉じられないままファイルが終わっています。この行以降が読み込まれません` |
| 辞書が読めない | `辞書を読み込めませんでした` |

- 辞書の読み込み前に行う `replace.txt` の置き換え（`【タブ】` をタブ文字にする書き方など）は、lint も同じように適用してから調べます。`＄` の行に「【タブ】」という文字が置き換えられずに残っているときは、メッセージの末尾に `（「【タブ】」という文字がそのまま書かれています。replace.txt に【タブ】をタブ文字に置き換える行を書くか、タブ文字にしてください）` が付きます。
- 式は、`＊名前【タブ】条件`、`＞飛び先【タブ】条件`、`＄名前＝式`、`when` などの特殊形式の式が対象です。式の中の `（…）` は実行時の値が分からないので、`1` に置き換えて `calc` に通します。`（）` を含む式で計算できないときは、error ではなく warning（`計算式を確認してください（（）を数値に置き換えて検査しました）：「1＋」`）にします。
- 内蔵関数の引数の個数は、`（set、a、b）` のように字面で決まるときだけ調べます。引数に入れ子の `（）` があると、展開後の区切りの数が変わるので調べません。

### warning

| 検出するもの | メッセージ |
|--------------|------------|
| `（名前）` の名前が、単語群・文・変数・内蔵関数・内蔵変数・SAORI のどれにも見つからない（辞書に、実行時に名前が決まる変数などを作る記述が**無い**とき） | `「名前」は、単語群・文・変数・内蔵関数・SAORIのどれにも見つかりません。…` |
| `（）` の中身が空で、名前の無い `＊` も `＠` も無い | `（） の中身が空で、名前の無い＊も＠もありません` |
| `＞` の飛び先や選択肢の ID が、無い文と、空白・全角半角・大文字小文字だけが違う | `ジャンプ先「フラグ処理 」という＊の文はありませんが、空白や全角半角・大文字小文字だけが違う「フラグ処理」があります` |
| `＠` の本文に、`＄名前【タブ】値` や `＄名前＝式` の行がある | `＠の本文では、＄の行は変数の代入になりません（単語としてそのまま使われます）。…` |
| `＿` の後に文字が無い、または長すぎる | `選択肢記法の後に文字列が存在しないので、無視されます`、`選択肢記法が長すぎるので、無視されます` |
| 文と単語群が同名 | `同じ名前「名前」の単語群と文があります。トラブルの元なので避けましょう` |
| 変数と、単語群・文が同名 | `変数「名前」と同じ名前の単語群か文があります。トラブルの元なので避けましょう` |
| `（` を閉じ忘れた疑い（続きの行が `＊` か `＠` で始まっている） | `（ が閉じられていない可能性があります（続きの行が＊か＠で始まっています）` |
| ファイルの最後が `φ` | `ファイルの最後がφで終わっています` |
| `（）` が深すぎる（200 段を超える） | `（）の入れ子が深すぎるので、これより内側は調べません` |
| `if` `unless` `iflist` `switch` `nswitch` `choice` の枝に、変数や単語を書き換える処理がある（Mc206-3以降） | `「if」は引数を先に展開するので、選ばれなかった枝も実行されます。枝に（set）があります。片方だけ実行したいときは、when か whenlist を使ってください` |
| 変数名の前か後ろに空白がある（Mc206-3以降） | `変数名「名前 」の前か後ろに空白があります。空白も含めた名前で登録されるので、空白なしの名前では読めません…` |
| `（乱数…）` の指定が変（`～` が 1 つでない。Mc206-3以降） | `「乱数～１」は、乱数の指定が変です。「（乱数1～6）」のように、～を 1 つだけ書きます` |

- 「`（笑）` のような、文字として表示したい `（` `）`」は、実行時には名前の検索に失敗して、そのまま表示されます。lint はこれを「見つからない名前」として警告します。表示のつもりなら `φ（笑）` と書くと、警告も実行時の `not found` ログも出なくなります。
- `ID` が `On` で始まる、`http` で始まる、`:` を含む（`script:` など）選択肢の飛び先は、イベントや URL として使われるので調べません。`OnChoiceSelect` を定義しているときも調べません。
- `\q[ラベル,ID,…]` は 2 つ目、`\__q[ID,…]` は 1 つ目を ID として読みます。`"…"` で括ったラベルの中の `,` や、`\]` は区切りとして扱いません。`\\q[…]` のようにバックスラッシュを重ねたものはタグとして扱いません。ID に `（）` を含むときは調べません。
- **`if` などの枝の処理**（Mc206-3以降）：`if` `unless` `iflist` `switch` `nswitch` `choice` は ssu の関数で、特殊形式の [when](../functions/when.md) と違い、引数の `（）` を先に全部展開します。このため、枝に変数や単語を書き換える処理があると、選ばれなかった枝でも実行されます（例：`（if、（Ｒ０）＜＝９９、（set、満充電、０））` は、Ｒ０ がいくつでも `満充電` を 0 にします）。片方だけ実行したいときは `when` か `whenlist` を使います（[if](../ssu/if.md)）。
    - 処理とみなすのは、`set` `変数の一括削除` `変数の一括コピー` `split_to` `単語の追加` `追加単語の削除` `追加単語の全削除` と、本文に `＄` の行（または上の処理）がある文を `（call、名前）` `（loop、名前、…）` `（vncall、名前）` `（名前）` で呼ぶことです。値を返すだけの文を呼ぶものは報告しません。
    - 枝として調べるのは、`if` `unless` `nswitch` は条件（先頭の引数）を除いたすべて、`iflist` `switch` は結果（と末尾の「それ以外」）、`choice` はすべての候補です。条件や比べる値の中の処理は、どの枝が選ばれても実行されるので報告しません。`when` などの特殊形式の引数の中は、条件によって実行されないことがあるので数えません。
    - 呼ぶ名前に同じ名前の `＠` があるときは、単語群として読まれ、どの単語が選ばれるか分からないので数えません。
- **変数名の空白**（Mc206-3以降）：`＄名前 ＝１`、`＄名前 【タブ】値`、`（set、 名前、値）` のように、名前の前か後ろに空白（半角・全角）があると、空白も含めた名前で登録されます。`（名前）` では読めません。空白だけの名前（`＄　【タブ】` で空文字列の定数にする書き方）は、意図したものとして報告しません。
- **`（乱数…）` の指定**（Mc206-3以降）：実行時と同じ分け方で、区切りの `～` が 1 つでない `（乱数…）` を報告します（実行すると `※　乱数の指定が変です　※` と表示されます）。

### notice

| 検出するもの | メッセージ |
|--------------|------------|
| `＞` の飛び先の文が無い | `ジャンプ先「名前」という＊の文が見つかりません。任意の飛び先として使っているのでなければ、名前を確認してください` |
| `＿ラベル【タブ】ID` `\q[ラベル,ID]` `\__q[ID]` の ID が文として無い | `選択肢の飛び先「ID」という＊の文が見つかりません。…` |
| `（名前）` の名前が見つからないが、実行時に名前が決まる変数などを作る記述が辞書にある | `「名前」は、単語群・文・変数・内蔵関数・SAORIのどれにも見つかりません。（実行時に名前が決まる変数や単語群を作る記述があるので、あるのかもしれません）…` |
| `（` に対応しない `）` | `対応する （ が無い ） があります。文字としてそのまま表示されます` |
| 行頭が半角の `*` `@` `$` | `行頭が半角の「*」です。この行は文の本文として扱われます（…）` |
| `（set、名前、…）` の名前が、単語群や文と同じ（Mc206-3以降） | `変数「名前」と同じ名前の単語群か文があります。トラブルの元なので避けましょう` |
| タブ区切りの代入が、自分自身に演算子をつないでいる（`＄回数【タブ】（回数）－１`。Mc206-3以降） | `タブ区切りの代入は計算せず、式を文字列として入れます。自分自身を含むので、実行のたびに式が長くなっていきます…` |

- 飛び先の無い `＞` は、実行しても、ログに `not found` と出て続きを実行するだけです。ひな形が用意する任意のフック（`＞他のゴーストから変更` など、定義するかどうかは作者しだい）として使われることが多いので、`error` にしていません。名前の書き間違い（末尾の空白など）は、上の warning で見つかります。
- `＞` の飛び先は、空（ランダムトーク）と `OnTalk` は存在しなくても報告しません。`≫` `≧` は検索なので調べません。飛び先に `（）` を含むとき（実行時に決まるとき）も調べません。
- `１）りんご` `a）` のように、`）` の直前が数字か英字のときは、箇条書きの番号とみなして報告しません。`φ（……）` のように、`φ（` で表示するつもりの `（` と対になる `）` も報告しません。
- 辞書の中に `＄（名前）＝…` `split_to` `単語の追加` のような、実行時に名前が決まる変数や単語群を作る記述があると、見つからない名前は notice になります（変数は辞書を読むだけでは無いと言い切れないため）。
- タブ区切りの代入（`＄回数【タブ】（回数）－１`）は式を計算せず、式の文字列をそのまま入れます（`5－1` のようになり、実行のたびに長くなります）。計算に使うときに式として評価されるので動いてしまい、そう書いている辞書も多いため、notice にとどめます。計算した数を入れたいときは `＄回数＝（回数）－１` と書きます。自分自身を含まない形（`＄名前【タブ】（x）＋１`）は、表示する文字（`[（x）/3]` など）と区別できないので調べません。
- `（set、名前、…）` の名前が単語群や文と同じ場合は、生成した名前に set する辞書などで数が多くなりやすいので、`＄` の行（warning）より軽く notice にしています。

## 名前の探し方（`（名前）` の警告）

`（名前）` の名前は、実行時と同じ順で探します。

1. SAORI・内蔵関数（`（set、…）` のように区切りの前の名前が、`＠SAORI` に書いた呼び出し名、`internal_` で始まる本体の内蔵モジュール、または内蔵関数）
2. 単語群（`＠`）
3. 文（`＊`）
4. 変数（`Ｒ０` `Ｈ１` `Ａ２` `Ｓ３` `Ｃ４` のような配列も含む）
5. 内蔵変数（`現在年`、`乱数…`、`文「…」の存在` など）。標準的なリクエストヘッダの名前（`Reference0` `ID` `Sender` `SecurityLevel` など）もここに含めます。

変数は実行時に決まるものがあるので、次のどれかに当てはまれば「ある」とみなします。

- 辞書に `＄名前＝…` や `＄名前【タブ】…` と字面で書かれている。
- `（set、名前、…）` で字面の名前に代入されている。`（loop、名前、…）` の `名前カウンタ` も同様。
- 読み込み時点で変数として存在する（セーブデータから復元されたものなど）。

実行時に名前が決まる書き方（`＄（名前）＝…`、`（set、（名前）、…）`、`split_to` `変数の一括コピー` `単語の追加` `load_saori`）が辞書にあると、見つからない名前は「あるのかもしれません」と注記します。

!!! warning "未定義の名前を warning にとどめている理由"
    変数は、SAORI の戻り値や実行時の計算などで作られることがあり、辞書を読むだけでは「無い」と断定できません。そのため、見つからない `（名前）` は error ではなく warning（実行時に名前が決まる変数などを作る記述が辞書にあるときは notice）です。

## 実行系との関係

lint は、文法を別に書き直さず、実行系が使う部品を共有しています。

- 辞書の前処理（`φ` `＃` カッコ内改行の連結 `replace.txt`）と、`＊` `＠` への分割
- `（）` の読み方（特殊形式の判定と引数の分け方）と、名前を探す順序
- 内蔵関数の表（名前・特殊形式かどうか・引数の個数・引数の意味）と、内蔵変数の表
- `＄` 行の分け方、式の計算（`calc`）

このため、新しい内蔵関数や内蔵変数が足されると、lint もそのまま新しい名前を知っています。
