# ACP 版との違い

Unicode 版（`Mc2XX`）は、ACP 版（`Mc1XX`、Shift_JIS ベース）から内部の文字列を Unicode にしたものです。多くの辞書はそのまま動きますが、次の違いがあります。

## 互換のない点・注意点

| 項目 | ACP 版 | Unicode 版 |
|------|--------|------------|
| 辞書の文字コード | Shift_JIS | Shift_JIS のほか UTF-8 も読める（自動判定） |
| セーブデータ | Shift_JIS | 常に UTF-8 で保存。読み込みは自動判定 |
| 自動ウェイト | Shift_JIS のバイト数で数える（全角 1 文字が 2） | 文字数で数える（全角 1 文字が 1）。日本語では約半分 |
| `calc` の文字列の長さ比較 | バイト数 | 文字数 |
| `（バイト値、n）` | 1 バイトの文字を返す | n を Unicode のコードポイントとして 1 文字を返す |
| SHIORI の通信 | Shift_JIS | リクエストの `Charset` に従う |
| SAORI・SSTP・ssu との通信 | ACP | UTF-8 |
| 括弧展開サイズ制限 | バイト数 | 文字数（実質約 2 倍） |
| サロゲートペア | 対象外 | 1 文字として扱う |
| コミュニケートの点数 | バイト数に基づく | 文字数に基づく（一致した語が全角のみなら同じ点数） |
| `sprintf` の `%s` の幅 | バイト数 | 半角換算（全角は 2）で数える |

## 引き継ぎに関する注意

- Unicode 版で保存した UTF-8 のセーブデータは、ACP 版に戻して読むと文字化けする可能性があります。
- 暗号化（`.sat`）の辞書やセーブデータは、Unicode 版でも読めます。書き出す暗号化セーブデータは、UTF-8 のバイト列を暗号化したものです。

## 直された不具合

Unicode 版の作成にともなって、次の不具合が直っています。

- ssu の `is_digit` で、第 2 引数が `int` 以外のときも整数モードになっていた。
- ssu の `join` で、引数が区切りだけのときに範囲外を読んでいた。
- ssu の `lsimg` が、Windows 以外で値を返さなかった。
- `）` の直前の処理で、1 文字多く削っていた箇所。
- 辞書フォルダの列挙に失敗したときの不具合。
- さくらスクリプトの `[` に `]` がないときの不具合。

## Mc201-2 での修正

- ssu の `split_string`: 最大個数に達したとき、2 文字以上の区切りの 2 文字目以降が残る不具合。
- ssu の `sprintf`: `%i` が 8 進になっていた（10 進にした）。`%.3s` のような文字列の精度が効かなかった。
- `calc` / `calc_float` の `^`: ビット XOR になっていた（べき乗にした。`calc_float` にも追加）。
- `calc` の `=~` `!~`: 常に `0` だった（部分文字列の判定にした）。
- `（直前の選択肢名）`: 常に空だった（選ばれた選択肢の ID を返すようにした）。

## Mc201-3 での修正

- SAORI や内蔵関数（`set`、`nop` など）の引数に、`（Ｒ０）` の値などから文字として `（…）` が入っていると、その `（…）` が結果を捨てる形でもう一度展開され、中身が余計に実行されていた（単語の選択や `set` などの副作用が起きていた）。
- 速度の改善:
  - 単語群・文を選ぶ時間が、要素の数に比例して長くなっていた（条件式のない群では、要素が変わるまで候補を作り直さないようにした）。
  - カッコの展開やトークの変換で 1 文字ごとにメモリを確保していて、長いトークほど文字数の割合以上に時間がかかっていた。

## 判定が変わるかもしれない点

- UTF-8 の辞書では、波ダッシュ（U+301C）や全角チルダ（U+FF5E）、マイナスの記号が Shift_JIS 由来の文字と別の文字になります。里々は両方を受け付けます（[文字コード](../grammar/14-charset.md#utf-8-辞書で使う記号)）。
- 内部の特殊表現に、Unicode の私用領域（U+E0FF ほか）を使います。辞書の本文にこれらを含めないでください。
