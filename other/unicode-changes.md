# ACP 版との違い

Unicode 版（`Mc2XX`）は、ACP 版（`Mc1XX`、Shift_JIS ベース）から内部の文字列を Unicode にしたものです。多くの辞書はそのまま動きますが、次の違いがあります。

## 互換のない点・注意点

| 項目 | ACP 版 | Unicode 版 |
|------|--------|------------|
| 辞書の文字コード | Shift_JIS | Shift_JIS のほか UTF-8 も読める（自動判定） |
| セーブデータ | Shift_JIS | 常に UTF-8 で保存。読み込みは自動判定 |
| 自動ウェイト | Shift_JIS のバイト数で数える（全角 1 文字が 2） | 文字数で数える（全角 1 文字が 1）。日本語では約半分 |
| `calc` の文字列の長さ比較 | バイト数 | 文字数 |
| `（バイト値、n）` | 1 バイトの文字を返す | n を Unicode のコードポイントとして 1 文字を返す |
| SHIORI の通信 | Shift_JIS | リクエストの `Charset` に従う |
| SAORI・SSTP・ssu との通信 | ACP | UTF-8 |
| 括弧展開サイズ制限 | バイト数 | 文字数（実質約 2 倍） |
| サロゲートペア | 対象外 | 1 文字として扱う |
| コミュニケートの点数 | バイト数に基づく | 文字数に基づく（一致した語が全角のみなら同じ点数） |
| `sprintf` の `%s` の幅 | バイト数 | 半角換算（全角は 2）で数える |

## 引き継ぎに関する注意

- Unicode 版で保存した UTF-8 のセーブデータは、ACP 版に戻して読むと文字化けする可能性があります。
- 暗号化（`.sat`）の辞書やセーブデータは、Unicode 版でも読めます。書き出す暗号化セーブデータは、UTF-8 のバイト列を暗号化したものです。

## 直された不具合

Unicode 版の作成にともなって、次の不具合が直っています。

- ssu の `is_digit` で、第 2 引数が `int` 以外のときも整数モードになっていた。
- ssu の `join` で、引数が区切りだけのときに範囲外を読んでいた。
- ssu の `lsimg` が、Windows 以外で値を返さなかった。
- `）` の直前の処理で、1 文字多く削っていた箇所。
- 辞書フォルダの列挙に失敗したときの不具合。
- さくらスクリプトの `[` に `]` がないときの不具合。

## Mc201-2 での修正

- ssu の `split_string`: 最大個数に達したとき、2 文字以上の区切りの 2 文字目以降が残る不具合。
- ssu の `sprintf`: `%i` が 8 進になっていた（10 進にした）。`%.3s` のような文字列の精度が効かなかった。
- `calc` / `calc_float` の `^`: ビット XOR になっていた（べき乗にした。`calc_float` にも追加）。
- `calc` の `=~` `!~`: 常に `0` だった（部分文字列の判定にした）。
- `（直前の選択肢名）`: 常に空だった（選ばれた選択肢の ID を返すようにした）。

## Mc201-3 での修正

- SAORI や内蔵関数（`set`、`nop` など）の引数に、`（Ｒ０）` の値などから文字として `（…）` が入っていると、その `（…）` が結果を捨てる形でもう一度展開され、中身が余計に実行されていた（単語の選択や `set` などの副作用が起きていた）。
- 速度の改善:
  - 単語群・文を選ぶ時間が、要素の数に比例して長くなっていた（条件式のない群では、要素が変わるまで候補を作り直さないようにした）。
  - カッコの展開やトークの変換で 1 文字ごとにメモリを確保していて、長いトークほど文字数の割合以上に時間がかかっていた。

## Mc201-4 での修正

- [load_saori](../functions/load_saori.md): 関数として登録されておらず、`not found` になって使えなかった。
- [文の数](../functions/talk-count.md): 名前だけが登録されていて、常に空文字列を返していた（`（文「名前」の数）` と同じ値を返すようにした）。
- [vncall](../functions/vncall.md): 呼び出し先が見つからないとき、最後の引数の展開結果を返していた（空文字列にした）。
- `（文「名前」の他）` `（単語群「名前」の他）` のように表にない書き方、表にない `（count名前）`、n のない `（FMO項目名）` が、見つからない名前ではなく空文字列になっていた（[状態・存在確認](../system/names-state.md)）。

## Mc201-5 での修正

- [calc](../ssu/calc.md) と式の計算（`＄名前＝式`、`（when、…）` など）: 数値が 32 ビットで、2147483647 を超えるとあふれていた（64 ビットにした）。あわせて、最小値を `-1` で割ったり、その余りを求めたりすると CPU の例外で異常終了するおそれがあったのを直した（商は最小値、余りは `0` になる）。

## Mc201-6 での修正

- tama（tamac）などのログ受信ツールへのエラーログ（`[ERROR]` の行）が正しく区切られず、遅れたり、つながったり、欠けたりしていた。あわせて、`calc` の失敗などの実行時エラーが `[ERROR]` として届かず、応答に `ErrorLevel: critical` も付かなかったのを直した。
- 内蔵の ssu を使っているとき（`saori\ssu.dll` のファイルがないとき）、SAORI のエラーログと `ErrorDescription` に、存在しない `saori\ssu.dll` のパスの代わりに `(internal ssu)` と表示するようにした（[SAORI](saori.md#エラー)）。登録された外部の `ssu.dll` は、従来どおり実際のパスが表示される。

## Mc201-7 での修正

異常終了・無限ループ・壊れた出力になっていた問題を直した。

- 内部で例外（メモリ不足・範囲外など）が起きても、ベースウェアごと異常終了しないようにした。そのリクエストは 500 で終わる（[エラーメッセージ](error-messages.md)）。`load` / `unload` も同様。
- [calc_float](../ssu/calc_float.md): 結果が 128 文字を超える値（`（calc_float、(10^300)）` など）でスタックのバッファがあふれて異常終了していた。24 桁を超える結果が壊れた文字列（`10000000000000001000000000.00000` に文字化けが混ざる）や空文字列になっていたのも直した。
- ssu の [substr](../ssu/substr.md): 開始位置が 1 以上で、長さが `2147483647` のような大きな数だと、異常終了していた。
- ssu の [sprintf](../ssu/sprintf.md): 末尾の `%` や `%z` のように正しくない指定で、`%` が消え、値も 1 つ使われていた（`%` をそのまま残し、値は使わない）。幅・精度に巨大な数を書くとメモリを使い果たしていたので、上限（幅 4096・精度 512）を付けた。
- [calc](../ssu/calc.md) の `文字列*数値`: 巨大な数値でメモリを使い果たしたり、空文字列で延々と回ったりしていた（4194304 文字までにした）。
- `＄Ｒ…` `＄Ｓ…` に巨大な番号（`＄Ｒ１０００００００００＝１` など）を代入すると、異常終了していた（[参照値](../system/names-refs.md)）。
- 辞書の拡張子・接頭辞を変えていて、名前が拡張子より短いファイル（`dic_x.txt` など）がフォルダにあると、辞書の読み込みで異常終了していた（[＄辞書拡張子](../system/vars-save.md#辞書拡張子辞書接頭辞)）。
- `≧` のコミュニケート検索（タグ検索）で、検索語が `「` で終わると異常終了していた。
- 内部の特殊表現に使う私用領域の文字（U+E0FF の後に U+E0FD / U+E0FC）が辞書や入力にあると、無限ループになっていた（文字列の終わりで止めて、その表現は無視する）。
- `times` `for` `while` `loop`: 結果が [＄括弧展開サイズ制限](../system/vars-limits.md#括弧展開サイズ制限)を超えたら打ち切る。`for` と `loop` は、終了値が `2147483647` だと終わらないことがあったのを直した。
- 展開中に `単語の追加` などで単語群が変わっても、選んだ単語の展開が壊れないようにした。`＄変数＝式` の代入先も、式の展開中に変数や `Ｒ`・`Ｓ` が増減しても壊れないようにした。
- イベントの Reference が足りないリクエスト（`Reference` のない `OnSecondChange` など）で、範囲外を読まないようにした（足りない分は空として扱う）。
- 選択肢の行（`＿`）の処理が、再帰のたびに 2KB のスタックを使っていたのを減らした。
- ツール（さとりて）: 出力が 4095 文字を超えると途中で切れ、終端がなくて壊れた文字列が表示されることがあった。SAORI Basic（コンソールアプリ）の呼び出しは、出力が 4KB を超えると 10 秒待たされ、ハンドルも漏れていた（出力を読みながら待つようにした。タイムアウトした相手のプロセスは終了させる）。

## Mc201-8 での修正

全体を読み直して見つかった、異常終了・無限ループ・挙動の誤りを直した。

- 呼び出しと繰り返しの合計回数の上限 [＄呼び出し総数制限](../system/vars-limits.md#呼び出し総数制限)（既定 100000）を追加した。深さは `＄呼び出し回数制限` で制限されていたが、分岐する再帰や、本体が空の長い繰り返し（`（times、１０００、（times、１０００、（times、１０００、）））` など）は終わらなかった。`while` の条件がいつまでも真のときも、ここで止まる。超えるとログに `呼び出し総数超過` と出る。
- `（）` の書き方の入れ子が極端に深いと、スタックを使い果たして異常終了していた（SAORI の返り値は再展開されるので、外部の文字列でも起こり得た）。1000 段までにした（[括弧の入れ子の深さ](../system/vars-limits.md#括弧の入れ子の深さ)）。[calc](../ssu/calc.md) と [calc_float](../ssu/calc_float.md) の式のカッコも、200 段までにした。
- 押しっぱなし（`○○ホールド` `○○ホールド終了`）の処理が、Reference の配列が空のときにも範囲外を読んでいた。長押しした後、すぐ別のクリックをすると起きた。
- [split_to](../functions/split_to.md): `接頭辞の数` の変数に巨大な値があると、前回の余りを消すために何十億回も回っていた（添字の上限 65536 までにした）。
- ssu の [reverse](../ssu/reverse.md): 長さの 2 乗の時間がかかり、長い文字列（20 万文字）で数十秒止まっていた。
- SAORI Basic（コンソールアプリ）: 出力し続ける相手だと、タイムアウト（10 秒）に達しても読み続けて戻れなかった。1 回に読む量と総量（16MB）に上限を付けた。
- ssu の [mkdir](../ssu/mkdir.md) と [lsimg](../ssu/lsimg.md) が、外部からのイベント（`SecurityLevel: external`）でも実行できていた。`local` のときだけ実行するようにした（ssu.dll を単体で使うときも、リクエストの `SecurityLevel` が `external` ならそうなる）。
- さくらスクリプトが `\p[2]` だけのトークが「空」と判定されず、何も喋らないはずのイベントで `\p[2]\e` を返していた。
- 文中の `%` タグの解釈: `%month` の直後に `day` が続くと `%day` になるなど、一致したあとも続きを別のタグとして読んでいた（`%selfname2` は先に判定するようにした）。
- [自動アンカー](../grammar/11-auto-insert.md): アンカーが隣り合っていると、2 つめがアンカーにならなかった（直後の 1 文字を飛ばしていた）。
- コミュニケートの検索: `「` だけの名前を持つ文が、先頭一致でも二重に候補に入っていた。また、採用条件が異なる同名の文が複数あると、候補が条件の数だけ重複して、選ばれる確率が偏っていた。

## Mc201-9 での修正

- YAYA as SAORI（`yaya.dll`）の古い `ayasaori.aym` を使っていると、最初の SAORI 呼び出しの引数や結果だけが文字化けしていた（Mc172-3 では起きていなかった）。`GET Version` の応答に `Charset` がない SAORI には、直後に何もしない `EXECUTE` を 1 回送って読み捨てるようにした（[SAORI の通信](saori.md#通信)）。

## Mc201-10 での追加

- YAYA と同じ `Set_loghandler` エクスポートを追加した。コールバックが設定されている間は、ログをウィンドウに送らず、YAYA と同じ形でコールバックに渡す（[ログ](../shiori/debug.md#ログ)）。
- tama へ送るログの終了の通知（`E_END`）の値が YAYA と違っていた（5 を送っていた。YAYA では 6）のを直した。

## Mc201-5 での追加

- 内蔵関数 [変数の一括削除](../functions/erase-variables.md)、[変数の一括コピー](../functions/copy-variables.md)、[変数の列挙](../functions/list-variables.md)：名前が接頭辞で始まる変数をまとめて扱う。
- 内蔵関数 [split_to](../functions/split_to.md)：`（S0）` などを上書きせずに、指定した接頭辞の変数に分割結果を入れる。
- ssu の [replace](../ssu/replace.md) と [erase](../ssu/erase.md)：置換の組・削除する文字列を複数書けるようにした（一度の走査で置換する）。

## 判定が変わるかもしれない点

- UTF-8 の辞書では、波ダッシュ（U+301C）や全角チルダ（U+FF5E）、マイナスの記号が Shift_JIS 由来の文字と別の文字になります。里々は両方を受け付けます（[文字コード](../grammar/14-charset.md#utf-8-辞書で使う記号)）。
- 内部の特殊表現に、Unicode の私用領域（U+E0FF ほか）を使います。辞書の本文にこれらを含めないでください。
